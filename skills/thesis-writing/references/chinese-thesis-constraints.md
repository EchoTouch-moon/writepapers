# Chinese Undergraduate Thesis Constraints

> 来源：国内计算机本科毕设论文LLM写作规范与约束手册
> 适配：国内高校计算机专业本科毕业设计评审标准

## Core Positioning

**工程实践能力**为核心考察目标：
- 完整技术闭环
- 规范学术格式
- 严谨逻辑链条
- 真实研究内容
- 严禁夸大创新、内容造假、学术不端

## LLM Role Boundary

LLM仅作为**辅助写作工具**，不得全文代写。所有生成内容必须经用户逐字审核。

## Pre-requirements (User Must Provide)

| Requirement | Specification |
|-------------|---------------|
| 课题全称 | 完整题目 |
| 核心技术栈 | 含版本号 |
| 学校模板 | 官方论文模板 |
| 字数要求 | 正文1.5w-3w字 |
| 重复率要求 | 符合学校标准 |
| 参考文献 | 用户已准备，LLM直接使用 |

**LLM严禁编造上述核心信息。**

## Chapter Framework

### Front Matter

| Module | Requirements |
|--------|--------------|
| 封面/原创性声明 | 按学校模板，LLM仅辅助填写个人信息 |
| 中英文摘要 | 300-500字，概括背景/目的/方法/成果/结论 |
| 关键词 | 3-8个，贴合课题核心 |
| 目录 | 到二级标题，与正文完全一致 |

### Chapter 1: 绪论 (2000-3000字)

**必备二级标题：**
- 1.1 研究背景与意义
- 1.2 国内外研究现状
- 1.3 主要研究内容
- 1.4 论文组织结构

**强制约束：**
- 研究现状100%基于用户提供真实文献
- 禁止"填补空白""首创"等夸大表述
- 所有引用必须上角标标注

### Chapter 2: 相关技术 (2500-3500字)

**核心要求：仅介绍本课题实际用到的技术**

**强制约束：**
- 禁止罗列无关技术
- 禁止大段摘抄官方文档
- 专业术语全文统一
- 公式/定理标注来源

### Chapter 3: 需求分析 (2500-3500字)

**必备二级标题：**
- 3.1 可行性分析（技术/经济/操作/法律）
- 3.2 功能性需求分析
- 3.3 非性需求分析（必须量化）
- 3.4 系统用例分析
- 3.5 数据流分析

**强制约束：**
- 所有需求与后续设计/实现/测试完全对应
- 图表必须有编号/标题，正文必须引用

### Chapter 4: 系统设计 (3000-4000字)

**必备二级标题：**
- 4.1 设计目标与原则
- 4.2 总体架构设计
- 4.3 功能模块详细设计
- 4.4 数据库设计
- 4.5 核心接口/算法设计

**强制约束：**
- 设计必须完全满足需求
- 数据库表结构必须与功能模块匹配
- 符合第三范式

### Chapter 5: 实现与测试 (4000-6000字，核心章节)

**必备二级标题：**
- 5.1 开发与运行环境
- 5.2 核心功能模块实现
- 5.3 系统测试
- 5.4 测试结果与分析

**强制约束：**
- 正文代码总占比≤10%
- 代码片段单段≤30行，带注释
- 测试用例必须完整（编号/模块/输入/预期/实际/结论）
- 性能测试必须有量化数据
- 禁止仅写"全部测试通过"

### Chapter 6: 总结与展望 (1000-1500字)

**必备二级标题：**
- 6.1 工作总结
- 6.2 未来展望

**强制约束：**
- 禁止重复前文
- 禁止天马行空展望
- 禁止夸大成果

### Back Matter

| Module | Constraints |
|--------|-------------|
| 参考文献 | GB/T 7714-2015，禁止编造，禁止非学术来源 |
| 致谢 | 真诚贴合实际，禁止抄袭模板 |
| 附录 | 完整代码/测试用例，LLM仅排版 |

## Red Lines (Absolute Prohibition)

### Academic Integrity
- ❌ 编造参考文献/作者/期刊/数据
- ❌ 抄袭不标注引用
- ❌ 洗稿、夸大成果

### Content Quality
- ❌ 无关冗余内容
- ❌ 通用模板化内容
- ❌ 空泛无量化表述
- ❌ 逻辑脱节/前后矛盾

### Format
- ❌ 擅改论文结构/模板
- ❌ 无编号/无引用图表
- ❌ 不规范的参考文献格式

### Code Display
- ❌ 正文代码占比超10%
- ❌ 大段贴代码

## Writing Style Norms

### Content Consistency
- 核心信息（课题/技术栈/版本/模块/指标）100%统一
- 专业术语/缩写/大小写全文统一

### Academic Expression
- 正式语体，禁止口语化/网络化
- 客观被动语态，避免第一人称过度使用
- 学术化改写，降低重复率

### Technical Accuracy
- 技术表述准确，符合官方定义
- 代码符合行业规范，带注释
- 需求-设计-实现-测试闭环

## Reference Requirements

参考文献由用户提供，LLM直接使用：

- 用户提供真实可检索的参考文献列表
- LLM严禁编造任何文献条目
- 格式符合 GB/T 7714-2015
- 正文引用角标与列表序号完全对应

**禁止引用：** 百度百科、知乎、CSDN、博客等非学术来源

## Test Case Format

必须包含：
- 用例编号
- 测试模块
- 输入条件
- 预期结果
- 实际结果
- 测试结论

核心功能至少1个测试用例。
